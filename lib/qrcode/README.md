`qrcode.php` here is generated by `tools/vendor-qrcode.php` from the untouched
upstream copy in `tools/upstream/` (neither ships). Changes:

1. moved into `namespace Asymetria\TeamCards\Vendor\Qr`;
2. global `define()` constants turned into namespaced `const`;
3. `createImage()`, `printHTML()` and `printSVG()` removed (the plugin draws its own output);
4. every `trigger_error( ..., E_USER_ERROR )` replaced by `throw new InvalidArgumentException()` with a fixed message (catchable, no deprecated constant, nothing unescaped).

Everything else is upstream code, unmodified. `tests/test-qr-vendor.php` checks
the result against upstream module for module, versions 1–40, levels L/M/Q/H.

Known upstream limits the plugin works around in `Qr_Service`:

- `getMinimumQRCode()` reads a capacity table that ends at version 10; beyond it
  the symbol is wrong. The plugin picks the version itself from the RS block table.
- Upstream raises errors with `trigger_error( E_USER_ERROR )` — fatal, uncatchable,
  and deprecated since PHP 8.4. The vendored copy throws `InvalidArgumentException`
  instead, and the plugin validates input so no error path is reached anyway.
- Automatic mode detection may treat UTF-8 as Kanji. The plugin always uses byte mode.
